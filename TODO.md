# ScamGuard Outcome List

- **Token, contract, and website submission flow** — Provide one input field where a user can paste a cryptocurrency token name, contract address, or website URL; accept Enter and a clearly labeled primary Analyze action; provide example inputs that can be selected without typing; show validation feedback for empty or unsupported values.
- **Transparent risk assessment result** — Display a clear Low, Medium, or High risk level and a numeric score after analysis; identify whether the target was interpreted as a token, address, or website; show the analyzed target, timestamp, and a concise explanation; label the result as an educational screening signal rather than a guarantee or financial advice.
- **Specific red flags and security warnings** — List each detected warning as a readable card with severity, title, explanation, and evidence/recommendation; distinguish positive signals from warnings; never claim live blockchain facts that were not retrieved from a configured endpoint.
- **Website and contract safety boundaries** — For website URLs, the server analysis route may inspect public HTTP metadata with safe protocol/host validation, timeout, bounded response reads, and explicit unavailable-data messaging; for contract/name inputs, use transparent heuristics and state that ownership, liquidity, permissions, and chain activity are not proven without a configured chain data provider.
- **Responsive ScamGuard interface** — Use the requested palette (#00C897, #1A1A2E, #121212, #E94560, #EAEAEA, #16213E), Inter/Roboto Mono-style typography, 24px spacing, 8px radii, clear risk iconography, card-based reporting, and a simple single-column flow that remains usable on mobile.
- **Full-stack Vercel-ready delivery** — Implement a frontend plus `/api/analyze` serverless backend, include local fallback behavior that is explicitly labeled when the API is unavailable, add route/build configuration for Vercel, and push the complete source to `bangke1212/Checker-Web_3-scam`.
- **Quality and recovery states** — Include loading, API unavailable, invalid input, empty result, recent scan, and reduced-motion-friendly states; keep prior result visible while a new scan is in progress; prevent duplicate submissions while analyzing.
